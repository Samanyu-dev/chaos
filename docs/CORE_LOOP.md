# 🔄 The Core Loop — Orbit (Chaos)

This document establishes the user engagement loop for Orbit (Chaos), explaining why friend groups use the platform before, during, after, and between trips.

---

## 🎯 Stage Breakdown: User Values

### ✈️ 1. BEFORE the Trip (Planning & Anticipation)
- **Why use it**: To co-create the spatial "Trip Planet" and coordinate agendas.
- **Core Value Actions**:
  - Friends vote on destinations and countdown visually via the floating **Trip Planet** dashboard cards.
  - Adding flight details updates the **Live Activity Widget** immediately.
  - Generating initial itinerary items in the capsule card deck to build anticipation.

### 📍 2. DURING the Trip (Coordination & Spontaneity)
- **Why use it**: Real-time navigation, social connection, and cost split tracking.
- **Core Value Actions**:
  - Tracking friends' spatial markers on the **Signal Tracker** maps instead of standard messaging logs.
  - Emitting neon signal reactions (floating emojis) to draw focus to points of interest.
  - Breaking decision paralysis via **Chaos Mode** roulette spins.
  - Instantly logging expenses (`💸` / `💳`) geolocated on the spot to avoid back-of-the-napkin math.

### 📸 3. AFTER the Trip (Memory Consolidation & Settlement)
- **Why use it**: Recalling the trip together and clearing balances.
- **Core Value Actions**:
  - Re-exploring the Shibuya canvas map to see geolocated **Parallel Memories**.
  - Comparing how Lila and Kai saw the same dinner from different perspectives in a single card stack.
  - Resolving splits with balance bubbles directly anchored to Shibuya coordinates.

### 👥 4. BETWEEN Trips (Perpetual Friendship Hub)
- **Why use it**: Staying connected, sharing inside joke coordinates, and preparing for the next planet.
- **Core Value Actions**:
  - Tapping geolocated **Inside Joke Quote Pins** anchored near home base coordinates to trigger chiptune sounds.
  - Syncing a shared music playlist that updates as friends listen.
  - Monitoring group streaks to prompt the next countdown.

## ✂️ Loop Alignment & Feature Pruning

Every active subsystem must directly serve one of these 4 phases. If a feature fails to drive the cycle, it is simplified or pruned:
1. **Dynamic Island Mockups**: Tied to active status updates (like countdowns or active chaos spins) to prompt users to launch the main loop.
2. **Simplified Sound System**: Synthesizing sounds dynamically keeps local app footprints light, ensuring smooth loading and high engagement on low-bandwidth networks during trips.
3. **Mock Data Seeding**: Serves as a sandbox template for new users, helping them understand the loop before initiating their first custom Trip Planet.
